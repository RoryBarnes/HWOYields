# HWO ExoEarth Yield: an AYO rederivation

A vaibify pipeline that rederives the Altruistic Yield Optimization (AYO) exoEarth-candidate
yield formalism of Stark et al. (2014, 2019, 2024) from the published equations and parameter
tables, and uses it to evaluate a counterfactual planet selection:

- planets selected by **mass**, 0.5–2 M⊕, with R = M^0.27, and
- a **habitable zone of 0.96–1.20 AU** for the Sun, scaled by sqrt(L) for every star,

against the canonical HabEx/LUVOIR exoEarth-candidate box (0.95–1.67 AU, R ≤ 1.4 R⊕).

## Headline results

| | Canonical box | Redefined box |
|---|---|---|
| Occurrence η | 0.217 (+0.128/−0.080) | 0.0439 (+0.0261/−0.0164) |
| Median expected yield (6 m) | 20.7 | 5.8 |
| P(≥ 25 candidates) | 32.5% | 0.05% |

Occurrence ratio **0.204 (+0.017/−0.016)**; yield ratio **0.280 (+0.028/−0.027)**. The yield
ratio exceeds the occurrence ratio because fewer expected detections free characterization time,
and because truncating the outer habitable zone preferentially removes the faintest planets.

**Validation:** before any calibration the model predicts 24.5 candidates against Stark's
published 22.5 (9%). Marginalised over the occurrence posterior it gives P(≥25) = 32.5% against
Stark's published 32% — a number nothing here was tuned to.

The full write-up, including limitations, is `doc/hwoYieldRederivationReport.pdf`.

## Pipeline

| Step | Name | Produces |
|---|---|---|
| A01 | buildTargetCatalog | Gaia DR3 + Hipparcos target list (8,709 stars within 50 pc) |
| A02 | modelCoronagraph | Mission parameters and coronagraph profiles |
| A03 | calibrateToStark | Throughput calibration against the published 22.5 |
| A04 | computeCompleteness | C(τ) per star, per selection box |
| A05 | optimizeSurvey | Equal-slope allocation and baseline yield |
| A06 | sampleOccurrencePosterior | emcee posterior over the SAG13 rate law |
| A07 | predictRedefinedYield | Marginalised yield distributions and the ratio |

`yieldlib/` holds the shared physics; `explorations/` holds exploratory scripts that are not
pipeline steps; `tests/` holds 45 library unit tests, and each step carries integrity,
qualitative and quantitative suites (91 tests) generated by introspecting its declared outputs.

## Running

```sh
python3 -m pytest tests/                 # library unit tests
cd doc && python3 buildReport.py --repo-root ..   # rebuild the PDF from step outputs
```

Steps should be run through `vaibify-do` once the project is opened in the dashboard.

## Requirements beyond the base image

`emcee>=3.1` and `pytest>=8.0` are **not** in the container image. They were pip-installed for
this session only. To persist them, add both to `pythonPackages` in the host's `vaibify.yml`
and rebuild the image.
