# HWO ExoEarth Yield: an AYO rederivation

A vaibify pipeline that rederives the Altruistic Yield Optimization (AYO) exoEarth-candidate
yield formalism of Stark et al. (2014, 2019, 2024) from the published equations and parameter
tables, and uses it to evaluate a counterfactual planet selection:

- planets selected by **mass**, 0.5–2 M⊕, with R = M^0.27, and
- a **habitable zone of 0.96–1.20 AU** for the Sun, scaled by sqrt(L) for every star,

against the canonical HabEx/LUVOIR exoEarth-candidate box (0.95–1.67 AU, R ≤ 1.4 R⊕).

## Headline results

| | Canonical box | Redefined box |
|---|---|---|
| Occurrence η | 0.256 | 0.0520 |
| Median expected yield (6 m) | 24.0 | 4.9 |
| P(≥ 25 candidates) | 48.6% | 0.21% |

Occurrence ratio **0.203 (+0.017/−0.017)**; yield ratio **0.204 (+0.019/−0.017)**. The yield
ratio exceeds the occurrence ratio because fewer expected detections free characterization time,
and because truncating the outer habitable zone preferentially removes the faintest planets.

**Validation: three compensating-error coincidences, now unpicked.** Out-of-sample checks
against Stark et al. (2024) drove three rounds of correction:

1. *Characterization* — the budget must charge a mean over the planets an exposure actually
   counts, not a median over all detectable ones, and planets that cannot be characterized within
   two months must not count at all. Fixing this took the aperture scaling from D^1.11 to
   **D^1.88** against a published ~D^1.9.
2. *Occurrence posterior* — the published eta was treated as a likelihood and multiplied by
   priors, giving an interval 23% **narrower than the constraint it was built from** with its
   right skew destroyed. Now sampled directly from the published posterior.
3. *Albedo and exozodi* — held fixed here, so this pipeline produces the **unbiased** yield while
   Stark's distributions and P25 values are biased ones (22.5 -> 17.3). Applying his own factor
   brings the mean to 20.5 against his ~21.

Each correction removed an apparent agreement: the 9% uncalibrated yield match, and the
P(≥25) = 33% vs 32% match, were both artifacts. The calibration gate now **fails** on factor
plausibility (3.84x), and P(≥25) here is 48.6% against a published 32% — not comparable until
albedo is modelled. Absolute yields are conditional; the box ratio at fixed aperture is the
robust quantity.

The full write-up, including limitations, is `doc/hwoYieldRederivationReport.pdf`.

## Pipeline

| Step | Name | Produces |
|---|---|---|
| A01 | buildTargetCatalog | Gaia DR3 + Hipparcos target list (8,709 stars within 50 pc) |
| A02 | modelCoronagraph | Mission parameters and coronagraph profiles |
| A03 | calibrateToStark | Throughput calibration against the published 22.5 |
| A04 | computeCompleteness | C(τ) per star, per selection box |
| A05 | optimizeSurvey | Equal-slope allocation and baseline yield |
| A06 | sampleOccurrencePosterior | emcee posterior over the SAG13 rate law |
| A07 | predictRedefinedYield | Marginalised yield distributions and the ratio |

`yieldlib/` holds the shared physics; `explorations/` holds exploratory scripts that are not
pipeline steps; `tests/` holds 45 library unit tests, and each step carries integrity,
qualitative and quantitative suites (91 tests) generated by introspecting its declared outputs.

## Running

```sh
# Does this reproduce the published results?  (pass/fail against Stark et al. 2024)
cd explorations && python3 checkAgainstPublishedValues.py --repo-root ..

# Does the pipeline reproduce itself?
vaibify-do run-all                                   # all seven steps
vaibify-do run-test-category <step> sCategory=quantitative
python3 -m pytest tests/                             # 45 library unit tests

cd doc && python3 buildReport.py --repo-root ..      # rebuild the PDF from step outputs
```

`checkAgainstPublishedValues.py` compares only values stated in the paper *text*, tags the
calibration row as tuned so it is never counted as agreement, and lists the stronger checks
(notably P25 vs aperture, Stark et al. 2024 Fig. 15) that have **not** been run. Section 4 of
the report sets out the full verification protocol, the differences you should expect and not
chase, and what would falsify the model.

Steps should be run through `vaibify-do` once the project is opened in the dashboard.

## Requirements beyond the base image

`emcee>=3.1` and `pytest>=8.0` are **not** in the container image. They were pip-installed for
this session only. To persist them, add both to `pythonPackages` in the host's `vaibify.yml`
and rebuild the image.
